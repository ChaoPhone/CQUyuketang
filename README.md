# 在线课程页面辅助脚本

一个运行在本地浏览器中的用户脚本，用于**自动播放在线课程页面的音视频**、设置播放倍速与静音，
并提供页面结构的自检诊断能力。本项目针对 **`courses.cqu.edu.cn`** 做了适配。

## 三、适配的技术依据

调研确认：目标站点是**雨课堂「专业版」的贴牌部署**，与 `yuketang.cn` 共用同一套前端代码，
差异仅在于域名、院校标识与后端集群。

| 证据 | 值 |
| --- | --- |
| `meta keywords` | 雨课堂, 清华大学, 智慧教学, 翻转课堂… |
| 静态资源路径 | `fe-static-yuketang.yuketang.cn/fe/static/pro/1.3.312/fe-proxtassets/` |
| 页面容器 | `<div id="app"></div>`（Vue SPA） |
| CSP 响应头 | 无 |

正因如此，播放器接管、反暂停、静音、倍速等核心逻辑可以整体复用，
适配工作集中在**路由识别**与**页面结构契约**两层。
详细的技术过程与调研证据见 [`docs/CQU-适配说明.md`](docs/CQU-适配说明.md)。

## 四、安装

> 前置条件：**请先在官方页面正常登录**，确认你能正常访问课程内容。

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/)（篡改猴）或 Violentmonkey；
2. 打开 [`cqu-yuketang.user.js`](cqu-yuketang.user.js)，**拖进浏览器窗口** → 弹出安装页 → 点「安装」；
3. **确认脚本已放行**：点浏览器工具栏的油猴图标 → 找到当前站点那一行 →
   若显示「已禁用 / 拒绝 / 需要点击」，改为**允许**。

> 第 3 步没做会完全没有反应：油猴显示"已启用"，但脚本在该站点不会注入，控制台也不会有报错。
> 这是最常见的安装失败原因。

## 五、使用

打开课程学习页面，左上角会出现面板：

| 按钮 | 作用 |
| --- | --- |
| `开始播放` | 启动：接管播放、静音、设定倍速、后台保持 |
| `诊断` | 复制完整诊断报告（含日志），用于排查问题 |
| `配置` | 设置大模型 API、播放倍速、可选功能开关 |
| `重载` | 刷新页面并自动恢复运行 |
| `清除` | 清除本地进度与跳转记录 |
| `停止` | 停止并解除静音、刷新页面 |

启动后可以**切标签页或最小化窗口**，脚本会继续到播放结束。

**面板操作**

- **拖动**：按住标题栏（避开右上角两个小按钮）拖到任意位置，拖到屏幕边缘会保留可抓取区域；
- **翻日志**：鼠标悬停在日志区滚轮，或点一下日志区后用上下方向键；
- **最小化**：点标题栏的 `–`，收起为小方块，点击展开。

**正常运行时的日志**

```
已找到 video 元素（位置：document）
已开始播放：2x，静音，后台挂机中
播放已确认推进，开始挂机等待完成
播放完成
```

看到「已开始播放」即表示接管成功。

## 六、常见问题

### 面板不出现

**第一步：F12 打开控制台，刷新页面，确认有没有这行日志**

```
[CQU雨课堂] 脚本已执行 v1.2.0
```

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 完全没有这行 | 脚本没运行 | ① 油猴中确认脚本**已启用**；② 确认**站点权限已放行**（见第四节第 3 步） |
| 有日志 + `当前在 iframe 内，按设计跳过注入` | 页面被框架嵌入 | 回到外层页面操作 |
| 有日志 + 页面出现红色提示框 | 面板挂载失败 | 把红框中的错误信息反馈到 Issues |
| 有日志 + 面板出现 | 正常 | — |

### 点「开始播放」没反应

点 `诊断` 查看输出：

- **关键契约未命中** → 页面结构有变，请把诊断报告发到 Issues；
- **媒体：命中根 = `(未找到)`** → 播放器位于**跨域** iframe 内，受浏览器同源策略限制无法穿透；
- **显示「浏览器拦截了自动播放」** → 点一下页面任意位置即可开始（仅需一次）。

### 诊断里的「其余未命中」要不要管

**不用管。** 未命中的契约分两类：

- **关键契约**：当前路由所需的媒体或目录节点，未命中才会影响对应功能；
- **可选契约**：`nextButton` / `batchItem` / `v2LogList` / `subjectItem` / `commentText` 等，
  均为**特定页面类型专用**。例如视频播放页上，作业相关的契约本来就应为空。

诊断按当前路由判断必需项：目录页检查目录节点，视频/音频页检查跨根媒体查找结果；不会要求一个视频页同时出现音频和目录。

v1.2.0 修复了面板随鼠标漂移、倍速设置回退、解除静音后仍无声、跨课程游标串用以及 SPA 跳转后运行中断等问题。完成判定仅接受 100%、明确完成状态、完整进度比或媒体结束；超时和未找到媒体都会留在当前页供重试。升级后旧的无课堂归属游标不再复用，会从目录开头重新检查完成状态。

### 播放守护（v1.2.0 新增，针对「经常卡住 / 无法连续播放」）

之前的实现在**暂停拦截**和**卡死检测**两处都有漏洞，导致播放容易中断或整轮卡住。v1.2.0 引入播放守护，改动集中在三个机制：

| 机制 | 说明 |
| --- | --- |
| **捕获阶段拦截** | 在 `document` 的捕获阶段监听 `pause` / `visibilitychange`，用 `stopImmediatePropagation()` 掐断。捕获监听先于事件到达目标执行，因此**无论平台何时注册、注册在哪个阶段，它的处理器都不会被调用** |
| **覆写 `pause()`** | 同时覆写 `HTMLMediaElement.prototype.pause`，堵住「平台直接调用 `video.pause()`」这条路径。采用双路覆写（`unsafeWindow` 与页面实际原型），以适配油猴沙箱 |
| **卡死看门狗** | 时间轴连续停滞 15 秒则主动 `play()` 一次；累计 3 次仍不动则刷新页面（自动化的「刷新即可」解法） |

`waitUntilDone` 也会检测进度停滞（约 24 秒无推进）后返回 `stalled` 而不是死等到超时，各运行器遇到 `stalled` 会**跳过该节点继续下一节**，而不是卡在原地反复重试 —— 这正是「不能连续播放」的直接原因。

守护只接管**时长 ≥ 30 秒**的媒体，避免误伤视频中弹出的题目弹窗与提示音；点「停止」会调用 `Player.shutdown()` 完整卸载守护并把声音交还用户。

本地回归说明见 [问题修复与回归记录](docs/问题修复与回归记录.md)。

## 七、已知限制

- **未在全部页面类型上验证。** 已用真实地址验证视频播放页；目录页批量处理尚无真实用例。
- 播放器若位于**跨域** iframe 内，无法穿透。
- 考试（`exam`）、直播/课堂（`live`）不做自动处理，仅跳过。
- 作业答题辅助依赖 OCR + 第三方大模型，**正确率不保证**，需自备 API Key；
  OCR 依赖按需懒加载，若 CDN 不可达会自动降级为纯文本识别。
- 目标站点当前无 CSP 响应头；若后续启用 CSP，注入方式需要调整。
